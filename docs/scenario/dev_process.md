# 剧本库开发流程（通用）

> 适用范围：以 `umaai-next` 为引擎的独立剧本仓。本文只收**怎么从一个空模板走到验收**——目标、
> 阶段步骤、留白项、常见坑、复制替换清单；**仓怎么组织**（crate 分工 / 数据配置 / 引擎钩子 /
> 文档体系 / 测试基线 / 分面 / 验收）见 [`repo_form.md`](repo_form.md)。
> 契约逐项见 [`contracts.md`](contracts.md)，接入纪律见 [`README.md`](README.md)。

## 1. 目标与非目标

**目标**：先与用户把剧本机制与用语核对清楚并落文档 → 在引擎契约上把机制跑通 → 手写策略覆盖全部
决策点 → 数值与旧实现对齐 → 固定种子基线锁定；同时验证引擎的契约、随机分层、注入点与 View 够用。

**非目标**：

- 不在剧本仓实现引擎通用能力（走 [`repo_form.md`](repo_form.md) §3 的钩子流程）；
- 不做通用算法工作台（调参 / 训练管线归独立项目）；
- 不做无消费者的呈现件（剧本特化面板等真实需求出现再做）；
- 不追求首版数值完全对齐——先结构后数值，逐批校正；
- 不在机制未确认时开工（见 §2.2 的阻塞闸门）。

## 2. 开发阶段

### 2.1 阶段总览

每步以「可交付 + 测试绿」收尾，不跨阶段堆改动；状态列由剧本仓按实际推进勾选。

| 步 | 内容 | 产出 | 验收 | 状态 |
|---|---|---|---|---|
| **S0 机制与用语文档核对** | 收集来源、起草术语与机制文档、逐条与用户核对、标确认状态 | 术语表 + 机制文档 + 数据清单 + 确认清单 | **无「机制未确认」项**；用户逐项确认并留记录 | ☐ |
| **S1 建仓与装配** | 复制模板、改名、依赖三档、CI、数据拷入、文档改名 | 可编译空壳 + 可启动 bin | `fmt` / `check` / `clippy` / `test` 绿 | ☐ |
| **S2 数据层** | 剧本资产 schema（serde + 严格校验）、剧本配置段（覆盖层语义） | `<剧本>Data` + `<剧本>Config` + 载入器 | 载入 / 缺字段 / 未知键 / 长度一致性单测 | ☐ |
| **S3 局面与阶段机** | `Game` 22 必备项、阶段枚举与 `StageId`、三轴随机、`fork_for_rollout` | 可推进的空局面 | 固定种子跑满回合、两次逐位一致、未注入主种子报错 | ☐ |
| **S4 动作与结算** | `ActionEnum` + `apply`、训练 / 比赛 / 休息 / 出行 / 治病 / PR 等动作集 | 动作全集与结算入口 | 单动作单测；`apply_root_action` 与 `run_stage` 逐字一致 | ☐ |
| **S5 机制** | 剧本资源系统、训练加成、特例公式、上限与分档 | 机制闭环 | 每条数值口径一个机制单测（公式 + 边界） | ☐ |
| **S6 事件** | 事件生成（固定回合 / 角色 / 随机分布）、结算与特例 | 事件链 | 固定回合事件、分布抽样、成功 / 失败分支 | ☐ |
| **S7 训练员** | 手写守门链 + 打分表 + 事件选项；需要搜索时实现 `FlatSearchGame` | 手写训练员（可选搜索） | 覆盖全部决策点、无死循环、搜索可复现 | ☐ |
| **S8 装配与呈现** | `build_game`、配置段接线、View 快照、`cli` 入口（离线 / 在线 / 手动档）与训练员选择器 | 可运行入口 | 一局端到端、View 序列化、未知选择器报错 | ☐ |
| **S9 基线、文档与验收** | 固定种子基线、测试一览、机制 / 术语 / 交接文档、README 状态 | 基线 + 文档 | 基线自动判定、文档链接可解析、四档全绿 | ☐ |

> S9 之后按需进入 §4 的性能优化轨（可选），不占主表状态列。

**模板边界**：模板只固化与剧本无关的接线（五 crate 布局、数据与配置载入、阶段投影、规则流接线、
测试定位、手动训练员）。**阶段与决策点、事件管线、训练管线、人头 / 比赛、资源账本**等强依赖
剧本的形态不预置实现，先在剧本仓 `docs/plan/scenario_dev_plan.md` 列为「待确认项」，S0 核对后
再逐项落。

### 2.2 S0：机制与用语文档核对（阻塞闸门）

剧本包含大量领域专属信息（机制名、日文原文、资源、事件、数值表、交互形态），**必须人工核对**，
不能靠推测。**S0 未通过不得进入 S1**：不允许「边开发边确认机制」。

**产出**：

- `docs/glossary.md`：术语单一事实源（中文 / 日文 / 旧仓标识 / 备注 + 口径与用语决定记录）；
- `docs/mechanism.md`：机制文档（回合与阶段、资源系统、训练与加成、比赛、事件、决策点、随机轴），
  每节带「实现落点」表（机制点 → 数据字段 → 阶段 / 动作 → 结算函数 → 测试）；
- `docs/plan/intake.md`：**接入包**——情报位置清单（官方 / 游戏内 / 数据表 / 真机帧 / 旧仓 /
  日文备忘 / 社区 / 用户口述等）、机制清单、数值清单、数据表清单、待确认问题；
- `docs/plan/stubs.md`：**数值占位登记**——`STUB` / `TBD` 的项、来源、存放位置、替换条件、基线影响；
- `docs/plan/scenario_dev_plan.md`：本剧本阶段状态与决策记录（方法见本文，不重复抄）。

**来源要标可信度**：真机帧 > 官方资料 > 旧仓实现 / 日文备忘 > 用户口述；冲突时以更新、更接近
真机的来源为准，并把分歧记入 glossary 的决定记录。

### 2.3 两种「未确认」口径

| 状态 | 含义 | 是否阻塞 | 处理 |
|---|---|---|---|
| **机制未确认** | 规则逻辑、触发条件、结算顺序、交互形态未知或存在多解 | **阻塞** | 不开发该机制相关功能点；若牵动阶段机 / 动作集 / 资源系统，**整个剧本库暂停**；反复与用户核对直到确认 |
| **数值待确认** | 机制已确认，具体数值 / 概率 / 上限 / 表项未到 | **不阻塞** | 用历史剧本同口径数值或 stub 代替；**集中存放 + 显式标记**，并在确认清单与机制文档登记 |
| **已确认** | 机制与数值都已确认 | — | 记录来源与确认日期；数值来源（真机 / 资料 / 旧实现）一并标注 |

- **机制未确认禁止「先写一版」**：错误机制会污染阶段机、动作集与基线，返工成本高于等待确认。
- **数值 stub 必须可整体替换**：集中在剧本资产 / 配置 / 常量表，命名带 `STUB` / `TBD` 标记，
  代码里不散落魔法数；文档同步标注「历史剧本口径 / 猜测 / 待真机」。
- **替换即重录**：stub 换成确认值后基线必然位移，重录并在 glossary 记原因与影响面。

### 2.4 与用户协作的流程

1. **列来源**：汇总真机帧、官方资料、旧仓实现、日文备忘、用户口述，逐条标来源。
2. **起草骨架**：先出术语表（中文 / 日文 / 旧仓标识），再按机制分组出机制文档草稿；不确定处标
   `❓`，**不写成结论**。
3. **分组核对**：按「回合阶段 → 资源 → 训练 → 比赛 → 事件 → 决策点」逐组问用户；一次只问一组，
   每次给出「当前理解 + 可能的另解 + 影响面」，例如：
   > 这一项目前理解为 X；另一种可能是 Y；它会影响 [阶段机 / 动作集 / 评分]；请确认是 X 还是 Y？
4. **允许「不确定」**：用户不确定时直接记「机制未确认」，不勉强给答案；列入待核对清单继续追问。
5. **记录决定**：确认结论写入术语表 / 机制文档，并在决定记录写日期、结论、影响（是否位移基线）。
6. **反复到清零**：直到确认清单里**没有机制未确认项**；数值待确认项可以保留，但必须逐条登记。
7. **开工走查**：进入 S1 前，把术语表 + 机制文档 + 数据清单 + 确认清单整体过一遍，逐节向用户
   复述关键机制；用户明确确认后才开工。

**确认清单模板**：

| 机制点 | 来源 | 状态 | 影响功能 | 备注 |
|---|---|---|---|---|
| 例：槽满转强化训练 | 真机帧 | 机制未确认 | 动作集 / 训练结算 | 槽值公式与是否可跳过待确认 |
| 例：强化等级上限 | 用户口述 | 数值待确认 | 训练表 | 先按基础档 stub，剧本友人的提升档待确认 |

### 2.5 阶段纪律

- **S0 闸门**：无「机制未确认」才开工；数值 stub 需在 S9 前替换，或明确登记为已知差异。
- **不预置剧本形态**：模板只给接线与骨架；阶段 / 事件 / 训练 / 比赛 / 资源等形态先列为待确认项，
  确认后再实现，避免把猜测固化成代码。
- 先骨架后机制、先手写后搜索；手写档交付后按 §3 的扩展轨接 MCTS / NN（sim / ai / tools 业务同理）。
- 有明确性能需求时按 §4 进入优化轨；没有配对测量不算收益。
- 机制改动在对应 crate 补测试，并同步更新测试一览。
- 数值位移先记 glossary 的口径决定，再重录基线；不默默改期望值。
- 每阶段结束跑一次四档（见 [`repo_form.md`](repo_form.md) §7），保持绿灯。

## 3. 训练员扩展轨（MCTS / NN）

> 手写训练员（S7）交付后按需进入本轨；两条轨都**不改引擎**，缺能力走
> [`repo_form.md`](repo_form.md) §3 的钩子流程。顺序上先 MCTS（先拿到可复现的搜索档），
> NN 轨本轮**只做特征定义与提取**，训练、推理与 leaf 估值接入不在本轮。

### 3.1 MCTS 接入规划

**前置**：S7 手写训练员可跑满回合并锁定基线；手写 rollout 训练员能独立跑完一局。

引擎侧只提供 `FlatSearch` 内核与 `FlatSearchGame` 适配层，**没有现成的「MCTS 训练员」**；
剧本仓自己实现一个 `Trainer` 包住搜索（下称 `MctsTrainer`）。

| 步 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **M0 搜索适配** | 为剧本实现 `FlatSearchGame`：`type RolloutTrainer` = 手写 rollout 训练员；`SUPPORTS_TRUNCATED_LEAF = false`；`default_rollout_trainer`；`apply_root_action` 与 `run_stage` 逐字一致；`fork_for_rollout` 克隆 + 注入 rollout 种子 + 重置自持策略流；`crn_stage_key` 默认 `StageId` | 可被 `FlatSearch` 驱动的剧本 | 同 `master` 两次搜索逐位一致；fork 后规则随机与主局一致 |
| **M1 决策接入** | `MctsTrainer` 实现 `Trainer`：动作决策点走 `FlatSearch`（候选 → `search` / `search_with_terminal` → 取中选动作）；事件选项继续走手写 `select_choice`；搜索不可用时回落手写 | 搜索版训练员 | 全部决策点有落手；搜索档与手写档可切换 |
| **M2 配置** | 搜索参数进剧本配置段（默认层 + 覆盖层）：`search_n` / `max_depth`（先固定 0）/ `use_ucb` / `search_group_size` / `search_cpuct` / `expected_search_stdev` / `pt_favor_rate` / `strict_rollout` / `parallel` | 剧本搜索配置 | 未知键报错；默认层可解析；不读引擎默认冒充剧本默认 |
| **M3 验证** | 固定根对照（同根两支、只改探测动作）、CRN 配对、跨种子复现、与手写档同卡组同种子对照；`SearchProbe` 记录候选数与耗时 | 对照报告 | 两次运行逐位一致；换 rollout 基策的实验开 `strict_rollout` |
| **M4 交付** | 搜索档单独基线（与手写档分开）、测试一览、机制 / 方案文档 | 可回归的搜索档 | 基线自动判定；文档写明与手写档不可混比 |

**约束**：

- **单一评分轴**：排序只走 `FlatSearchGame::search_score`，PT 偏好经 `pt_favor_rate` 折算；
  需要原始分时作为终局观测输出，不加第二评分轴。
- **rollout 基策即教师**：换基策等于换教师，旧分数与基线不可比；对照实验显式记录基策。
- **截断档不静默降级**：`max_depth > 0` 需要 leaf 估值器；未接入前保持
  `SUPPORTS_TRUNCATED_LEAF = false`，搜索入口会直接拒绝。
- **随机源**：决策流只吃 `run_stage` 传入的 `rng`；搜索分支只能经 `fork_for_rollout` 建，
  不自建主种子或第二套对齐。
- **并行只影响耗时**：`parallel` 关闭时降级串行，结果应逐位一致。

### 3.2 NN 接入规划（仅特征定义与提取）

> 本轮**不训练、不推理、不接 leaf 估值**；只把「喂给模型什么」定义清楚，并能确定性地导出。

| 步 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **N0 定义维度** | 冻结三类特征：局面状态、候选动作、终局目标；写清字段、顺序、归一化与缺失哨兵 | 特征规格（维度表） | 每个维度有来源字段与口径说明 |
| **N1 提取实现** | 剧本侧 `features` 模块：`encode_state(&game)` → 定长向量 + 动作编码；纯函数、只读、无随机、无副作用 | 编码器 + `INPUT_DIM` / `FEATURE_VERSION` 常量 | 同局面两次编码逐位一致 |
| **N2 校验** | 维度 / 范围 / 确定性单测；golden 快照（向量或哈希）守门 | 编码守门测试 | 改序 / 改宽必须显式 bump 版本 |
| **N3 导出** | 特征 + 动作索引 + 搜索分数 / 终局记录（`record_ordered_rollouts`）导出为离线数据集 | 样本导出接口 | 只导出不训练；样本可复现 |
| **N4 引擎接缝（延后）** | 引擎目前无 `Evaluator` / leaf 估值器；将来需要时按钩子流程加（带默认、默认不启用） | 钩子方案 | 未接入时 `SUPPORTS_TRUNCATED_LEAF` 保持 `false` |
| **N5 明确不做** | 数据集规模化、训练、onnx 推理、候选剪枝 / 打分接入、leaf 截断 | — | 另立方案 |

**特征分块（建议）**：

- **局面状态**：回合 / 阶段 / 年、五维、体力 / 干劲、技能点、PT、剧本资源、人头分布 / 羁绊 / 红点、
  训练等级、卡组与固有效果、flag / 病。
- **候选动作**：动作类型、训练种类、预期加成 / 得分、失败率、消耗、事件选项组。
- **终局目标**（标签侧）：终局评分、五维、PT、剧本资源；本轮只定义，不计算训练目标。

**纪律**：

- 特征只读局面，不写回、不触发随机；编码结果与运行顺序无关。
- **维度是契约**：改序、改宽、改归一化都要 bump `FEATURE_VERSION`，旧数据集与模型随之失效。
- 引擎字段与剧本字段分块，块内顺序稳定；引擎侧字段名走单一出口，不手抄第二份。
- 训练 / 推理的重依赖不进 `core`：归独立项目或 `tools` 面。
- 将来若把模型接进搜索，**优先候选剪枝 / 打分**（每决策一次推理），不做逐 rollout 的叶子前向。

## 4. 性能优化轨（可选）

> 完整方法、工具选择、测量协议与手段清单见 [`perf_plan.md`](perf_plan.md)。本节只给流程位置与准入。

**准入**：S9 基线已锁定，且出现明确的性能需求（在线决策延迟 / 搜索成本 / 批量跑局时长）。
**不做**：没有配对测量的「感觉更快」；不以牺牲行为一致性换速度。

| 步 | 内容 | 验收 |
|---|---|---|
| **O0 基线锁定** | 固定构建 / 工具链 / 数据 / 配置 / 种子 / 线程，记录生产参数 | 同参数两次运行逐位一致 |
| **O1 剖面定位** | 先 microbench 拿分段绝对成本，再整局 A/B 定端到端方向；pprof 只作高频线索，不用于判收益 | 热点以专用测试数据为准，多轮稳定 |
| **O2 单点改造** | 一次只改一个点，保持 RNG 调用、遍历与浮点运算顺序 | A/B 非耗时输出逐位一致 |
| **O3 回归验收** | 针对性 Release 测试 + 全量测试 + 固定根 + 整局对照 | 四档全绿；收益与范围写明 |
| **O4 固化** | 保留探针 / 微基准入口与命令，清理临时产物 | 命令可复跑；产物不入仓 |

**关键纪律**：

- **测速与行为分离**：耗时只在本机当轮有效；行为一致性用排除耗时字段后的 CSV 与固定根统计位模式判定。
- **数值位移即口径变更**：重录基线 + glossary 记录原因与影响面。
- **依赖归位**：探针 / pprof 依赖只在 `sim` / `tools` 且特性门控，不进 `core`，不进下游依赖链。
- **旧仓数字只作方向参考**（`perf_plan.md` §4 / §7），不迁移成本仓承诺。

## 5. 留白项（每个剧本必须替换）

| 面 | 要替换的内容 |
|---|---|

## 6. 常见坑

- **机制未确认就开工**：错误机制会污染阶段机、动作集与资源系统，返工成本最高；S0 闸门不可跳过，
  也不要用「先写一版再改」绕过。
- **stub 数值散落代码**：无法整体替换与盘点；stub 集中到资产 / 配置 / 常量表并统一标记 `STUB` /
  `TBD`，替换后重录基线。
- **把数值待确认当成机制未确认**：数值缺失可以用历史口径或 stub 推进，不必整体停摆；分清两类
  状态才不会卡死进度。
- **`Deref` 底座与契约同名**：同名方法会静默解析到基座版（编译过、行为错位）。基座入口叫
  `init_rule_streams`，契约叫 `set_rule_master`。
- **策略流未派生**：推进时报「策略流缺失」；只在主种子注入与回合边界重置。
- **主种子未注入**：推进会报错；不要加回退分支，也不要在剧本侧另建一套种子。
- **`fork_for_rollout` 未重置自持流**：可复现性与 CRN 一起静默失效，且不会报错。
- **重新引入外挂「按阶段重播种」**：配对已由每回合派生承担，不要再加第二套对齐机制。
- **搜索截断档**：`SUPPORTS_TRUNCATED_LEAF = false` 的剧本，搜索入口直接拒绝 `max_depth > 0`，
  不静默降级。
- **配置 / 资产宽松解析**：未知键、未知字段必须报错，拼错要被看见。
- **人头下标写死**：卡片前缀与卡组逐槽同序、非卡人头尾部追加；定位用
  `person_index_of_type` / `person_index_of_card`，数据表不带写死的 `person_index`。
- **测试 cwd 假设**：workspace 化后测试进程 cwd 在 crate 目录；用 `<剧本>_core::testing` 定位仓根，
  不要用引擎 `umaai-core::testing` 的 `env!`（固化引擎仓路径）。
- **独立 workspace 命令**：在引擎仓内跑模板一律带 `--manifest-path` 与 `--workspace`；
  复制出仓后从仓根执行。
- **并发 cargo**：同一 target 目录一次只跑一个 cargo，否则互等锁表现为卡死。
- **基线 `meta` 放路径**：会泄露目录结构；`meta` 只记版本与日期。
- **数据升级不重录基线**：引擎静态表变更后必须重拷并重录，否则基线漂移无从归因。

## 7. 复制后替换清单

> 前提：S0 机制与用语文档核对已通过（§2.2）——确认清单里没有「机制未确认」项。

1. 复制**整个模板目录**（不要只复制 `crates/<剧本>-core`），保留根 `[workspace]` 表。
2. 替换 5 个 package 名、bin 名与全部 `use <模板>_core::…` 引用（含 `Cargo.toml` 的
   `<模板>-core.workspace = true`）。
3. 调整引擎依赖三档：开发期 `path` → 稳定期 git `tag` → 下游 `default-features = false`。
4. 把引擎 `gamedata/` 的六张静态表与 `ai_config.toml` 拷入 `data/`，替换剧本资产与剧本配置默认层。
5. 填阶段、动作、结算、事件、机制、训练员与 View 字段；补机制测试与固定种子基线。
6. 更新文档：README / AGENTS / `docs/` 四件套中的剧本名、数据说明、验收命令与链接。
7. 改 bin 的 `DATA_ROOT` 与训练员选择器；按需增加手动 / 在线外壳。
8. 改 CI 名称与路径，确认四档守门与本地一致。
9. 建仓根 `baselines/` 并在文档写明重录命令。
