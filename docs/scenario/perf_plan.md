# 性能优化计划（剧本仓通用）

> 依据旧仓 `perf_profiling` 的方法论改写，并按**当前 `umaai-next` 已落地项**重排，面向独立剧本仓。
> 目标：**不改变决策语义**的前提下降低单局 / 搜索耗时；每次优化都要有配对测量与逐位一致验收。
> **工具优先级：专用测试（microbench / 整局 A/B / 固定根探针）> pprof 线索。**
> 剧本仓范围的改动走本文；**引擎侧优化走** [`repo_form.md`](repo_form.md) §3 的钩子流程。
> 流程位置：主阶段 S9 之后按需进入（见 [`dev_process.md`](dev_process.md) §4）。

## 摘要

- **先测量后优化**：没有配对测量（同种子、同配置、交替 A/B）就不认收益。
- **专用测试优先**：先用 microbench 拿绝对 ns/op，再用整局 A/B 与固定根验证端到端；
  pprof 只能提示「哪里被频繁调用」，**高频不等于耗时最高**，只作线索。
- **一次只改一个点**：组合收益必须拆分归因，或明确写「未拆分」。
- **行为不变**：排除耗时字段后，结果与决策记录逐位一致；固定根比较候选次数、统计位模式、
  终局统计与最优动作。
- **数值位移 = 口径变更**：重录基线，并在 glossary 记原因与影响面。
- **临时产物不进仓**：测量 CSV、探针程序、补丁等放构建目录 / 日志目录，不提交。

## 2. 基线环境

| 项 | 要求 |
|---|---|
| 构建配置 | 双方一致（沿用 workspace Release；不临时改 opt / LTO / codegen） |
| 工具链 | 同一 Rust / LLVM 版本；跨版本不比较绝对耗时 |
| CPU 目标 | 当前仓未启用 `target-cpu=native`；若为实验启用，只对该机有效，跨机 / 发布不可比 |
| 数据 | 同一份 `data/`（引擎六表 + 剧本资产）；schema 版本一致 |
| 配置 | 同一份搜索 / 模拟参数；测量入口自持输入，不读宿主覆盖层 |
| 种子 | 固定基础种子；配对双方跑同一批种子 |
| 线程 | 显式固定；线程数变化视为换了测量条件 |

## 3. 工具选择（优先级从高到低）

| 优先级 | 工具 | 用途 | 说明 |
|---:|---|---|---|
| 1 | **microbench**（测试或 `sim` 工具） | 单函数 / 按数据流分段的 ns/op | 首选；warmup + 多轮取稳定轮；给 pprof 给不出的绝对成本与段占比 |
| 2 | **整局 A/B**（`bench` / `compare`） | 端到端耗时与行为一致性 | 固定卡组 / 种子 / 配置，交替跑多轮 |
| 3 | **固定根探针**（`FlatSearch::with_probe`） | 搜索成本 | `SearchProbe` 记候选数、计划 / 成功 / 失败次数与耗时 |
| 4 | **pprof**（可选） | 高频调用点线索 | 采样能看「哪里被频繁调用」，但**调用频次 ≠ CPU 占比**；只用来挑 microbench 的目标 |
| — | ~~cargo flamegraph~~ | — | **本仓不采用**，不做相关准备与复现步骤 |

- **pprof 的正确用法**：先由 pprof 找候选函数，再用 microbench 测绝对 ns 与占比；判定收益以专用测试为准。
- **探针依赖归位**：pprof / 微基准依赖只在剧本仓 `sim` / `tools` 且特性门控，不进 `core`，不进下游依赖链。
- 引擎侧已有 `umaai-tools probe`（基础局）与搜索探针接口；剧本仓的固定根探针复用同一套
  `SearchProbe` / `FlatSearch`，不另写一套统计。

## 4. 测量协议

1. **配对交替**：A/B 双方交替先跑，避免单侧吃到机器负载漂移；每轮独立启动。
2. **整局**：固定卡组 × 固定种子，多局 × 多轮；报告每轮均值 / 中位数与波动，不用单局定论。
3. **固定根**：手写策略正常推进到目标回合（中段 / 后段训练回合），固定局面与搜索种子；
   交替三轮取中位数；记录候选数、实际预算、统计位模式、终局统计、最优动作。
4. **微基准**：固定 warmup 与迭代数，多轮取稳定轮；用「未改动的对照段是否回落基线」判可比性。
5. **逐位一致**：排除 `elapsed*` 字段后，结果 CSV / 决策日志的表头、行序与字段一致；
   浮点统计用位模式比较，不只比显示精度。
6. **跨次 / 跨机不可直接比**：不同批次数字用对照段或进程内对照锚定；绝对耗时只声明本机当轮。

## 5. 待评估的优化手段

> 已落地项见 §1，不再列出。按预期收益排序，实际以测量为准。

| # | 手段 | 典型内容 | 风险 / 注意 |
|---:|---|---|---|
| 1 | **减少分配与拷贝** | 容量复用（清空不释放）、借用替代 clone、栈数组、去临时 Vec | 借用生命周期要收窄；不能改变遍历顺序 |
| 2 | **收口重复计算** | 训练评估单源、评分缓存、选面预演副本复用 | 缓存只在局面不变时复用；写清失效条件 |
| 3 | **rollout 关明细** | 原因文本 / 评分分解开关：普通实例开、rollout 关 | 正常日志与协议摘要保留；只关不用的文本 |
| 4 | **搜索预算** | 按实测调 `search_n` / UCB 参数（高预算边际收益需实测） | 分数会位移；另立基线，不与旧档混比 |
| 5 | **并行粒度调优** | 线程数、分组粒度（并行实现已存在） | 只调参不改序；资源占用要记录 |
| 6 | **算法层** | 候选剪枝 / 先验打分（每决策一次推理） | 不做逐 rollout 叶子前向；需另立方案 |

## 6. 优化阶段 O0–O4

| 步 | 内容 | 产出 | 验收 | 状态 |
|---|---|---|---|---|
| **O0 基线锁定** | 固定构建 / 工具链 / 数据 / 配置 / 种子 / 线程，记录生产参数 | 基线数据 + 环境清单 | 同参数两次运行逐位一致 | ☐ |
| **O1 剖面定位** | 先 microbench 拿分段绝对成本；整局 A/B 定端到端方向；需要时用 pprof 找高频点再回测 | 热点清单（函数 / 段 / ns / 占比） | 多轮均值稳定，对照段回落基线 | ☐ |
| **O2 单点改造** | 一次一个改动，保持 RNG 调用、遍历与浮点运算顺序 | 单点补丁 + 针对性测试 | A/B 非耗时输出逐位一致 | ☐ |
| **O3 回归验收** | 针对性 Release 测试 + 全量测试 + 固定根 + 整局对照 | 对照报告（表 + 结论 + 范围） | 四档全绿；收益与范围写明 | ☐ |
| **O4 固化** | 保留微基准 / 探针入口与命令；清理临时产物 | 文档 + 可复现命令 | 命令可复跑；产物不入仓 | ☐ |

## 7. 验收清单

- `fmt` / `check` / `clippy -D warnings` / `test --release` 全绿；
- 针对性测试覆盖改动路径（含边界与失败分支）；
- 整局与固定根的非耗时输出一致（写明比较范围与精度限制）；
- 若数值位移：重录基线 + glossary 记口径与影响面；
- 无新增核心层依赖；探针依赖只在 `sim` / `tools` 且特性门控；
- 测量报告记录：提交版本、构建配置、数据版本、输入、种子、线程、命令。

## 9. 常见坑

- **单次采样就下结论**：抖动会盖住真实差异；至少多轮取中位数，并看对照段。
- **把 pprof 高频当高耗时**：高频函数可能很便宜；必须用 microbench 实测绝对成本后再排优先级。
- **只比耗时**：行为已变却看不出来；必须比非耗时字段与固定根统计位模式。
- **跨次 / 跨机直接比数字**：CPU 目标、负载、工具链都会影响；用同轮配对。
- **优化改动 RNG 顺序**：调用次数或顺序一变就是口径变更，先记 glossary 再重录基线。
- **临时产物入库**：探针程序、测量 CSV 体积大且易过期；只保留文档与命令。
- **并行带来的内存与线程本地状态**：同时存活的局面副本、线程本地模型都会增加；记录资源代价。
