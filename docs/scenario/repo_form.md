# 剧本仓形态（通用）

> 适用范围：以 `umaai-next` 为引擎的独立剧本仓。本文只收**仓怎么组织**——crate 分工、数据与配置、
> 引擎钩子、文档体系、测试与基线、业务分面、验收口径；**开发步骤见** [`dev_process.md`](dev_process.md)，
> 契约逐项见 [`contracts.md`](contracts.md)，接入纪律见 [`README.md`](README.md)。
> 本文与具体剧本无关；剧本名、机制、数值、术语与基线由各剧本仓自持。

## 摘要

- **独立仓**：剧本仓以依赖引用引擎 `umaai-core` / `umasim` / `umaai`（开发期 `path`、稳定期 git `tag`），
  不 fork 引擎、不在引擎仓加剧本 crate。
- **五 crate**：`<剧本>-core` 是宿主稳定面（机制 + 训练员 + 装配 + 快照）；`sim`（离线模拟）与
  `ai`（在线决策）是两条业务线 lib，`cli` 是唯一终端入口，`tools` 是外围工具面。
- **交付物**：lib 为主、bin 为辅；入口是可调用的装配 API，bin 只是主线自测外壳。
- **数据自持**：`data/` 是唯一发布库（引擎静态表 + 引擎配置默认层 + 剧本资产 + 剧本配置默认层），
  拷仓即跑。
- **配置双层**：默认层在数据根、覆盖层在宿主目录；同名才合并、段缺失整段沿用、未知键严格报错。
- **引擎零改**：接入新剧本时引擎仓 `git diff` 为空；确需新能力时回引擎按「带默认实现、非破坏」加钩子。
- **可复现**：局面流 / 事件流归 `BaseGame`、策略流自持、决策流只喂 `Trainer`；阶段自持、对外只投影
  `StageId`。
- **前端解耦**：剧本资源走 View 快照（形态 A），不进契约 trait。

---

## 1. 仓形态与 crate 分工

**形态：workspace 五 crate，按终端业务形态划分。** 根 `[workspace]` 表保留，使剧本仓可独立构建；
成员表只登记真实存在的 crate 与依赖，不做空转声明。

分工可以概括为「两条业务线 + 一个共享本体 + 一个终端入口 + 一个工具面」：

- **离线模拟线**：`sim` 负责跑一局 / 批量跑局 / 基线 / 测卡测量；
- **在线决策线**：`ai` 负责吃在线帧、走 `Session`、产出决策；
- 两条线共用 `core` 的剧本机制与训练员；**终端入口统一由 `cli` 承载**（两条业务线各一档入口）；
- `tools` 是外围工具面（测卡 / 复盘），不属于上述两条运行线。

**业务 crate 只出 lib，bin 只出现在入口 crate**（`cli` 与 `tools`）：同一业务线不允许出现两套入口逻辑。
Web / Android 宿主直接调用 `core` / `sim` / `ai` 的 lib，不经过 `cli`。

| crate | 业务 | 入口 | 依赖 |
|---|---|---|---|
| `<剧本>-core` | 剧本机制本体 + 训练员 + 装配 + View 快照（**宿主稳定面**），不承载具体业务 | 无独立入口（上层业务 / 宿主调装配 API） | 引擎稳定面（`umaai-core` / `umasim` / `umaai`） |
| `<剧本>-sim` | **离线模拟业务**：跑一局、批量跑局、固定种子基线、测卡测量函数 | `cli` 的离线档（或宿主持有 lib） | core + 引擎工具件（业务落地时登记） |
| `<剧本>-ai` | **在线决策业务**：剧本帧段解析、`Session` 接线、决策循环 | `cli` 的在线档（或 Web / Android 宿主） | core + `umaai`（业务落地时登记） |
| `<剧本>-cli` | **终端入口**：装配离线 / 在线 / 手动训练员，负责参数、呈现与退出码 | 唯一终端 bin 面 | core + `umaai-cli` 呈现件（样例面，pub 面不承诺；sim / ai 业务落地时登记） |
| `<剧本>-tools` | **外围工具**：测卡 / 复盘（复用引擎 `deck` / `arms` 内核） | 自带单 bin 多子命令（可按需挂 `cli` 子命令） | core / sim + 引擎工具件（业务落地时登记） |

- **依赖方向**：core 不依赖任何业务 crate；sim / ai 依赖 core 与引擎件；cli 依赖 core / sim / ai；
  tools 依赖 core / sim；业务 crate 之间不允许反向依赖（sim / ai 不得依赖 cli）。
- **入口纪律**：bin 只做参数解析、装配、错误与退出码；业务逻辑留在对应 lib，便于宿主复用与集成测试注入。
- **终端依赖只在 cli**：sim / ai / core / tools 不引终端呈现类依赖；呈现原语复用引擎 `umaai-cli`。
- **模板边界**：模板只固化与剧本无关的接线（crate 布局、数据与配置载入、阶段投影、规则流接线、
  测试定位、手动训练员）；阶段与决策点、事件管线、训练管线、人头 / 比赛、资源账本等**强依赖剧本
  的形态不预置实现**，先在剧本仓开发计划里列为「待确认项」，S0 核对后再逐项落。
- **可见性**：crate 内跨模块调用标 `pub(crate)`；跨 crate 消费的面标 `pub`（宿主面 = 装配 / View / 训练员）。
- **契约 trait impl 不可拆文件**：一个 trait 的 `impl` 必须整体落在同一文件（`Game` 的 22 个必备方法
  只能随它一起放 `traits.rs`）；可拆的只有 inherent `impl`。
- **`lib.rs` 只放声明与重导出**（模块声明 + 对外重导出 + 常量），实现落对应功能模块；
  改机制时先落模块，不把新逻辑堆回 `lib.rs`。
- **重依赖各归其位**：终端依赖只在 cli、并行与文件监听按业务登记；对应业务真正用上之前不往
  `Cargo.toml` 加依赖或 feature。
- **阶段自持**：内部强类型枚举，对外只投影 `StageId`（显式赋号，**改号 = 旧种子与基线失效**）。

## 2. 数据与配置

- **统一数据目录 `data/`（唯一发布库，拷仓即跑）**：
  - 引擎六张静态表（`cardDB.json` / `umaDB.json` / `events.json` / `text_data_dict.json` /
    `constants.json` / `manifest.json`）；
  - 引擎配置默认层 `ai_config.toml`；
  - 剧本资产（如 `scenario_<剧本>.json`）与剧本配置默认层（如 `<剧本>_config.toml`）。
- **建仓时拷入引擎数据**；引擎数据升级时**整目录重拷并重录基线**（基线由剧本仓自持）。
- **配置两份、同名不同位**：数据根内的是默认层（唯一默认源，字段齐全），宿主目录内同名文件是
  覆盖层（存在才合并、段缺失整段沿用、字段级覆盖）。剧本专属配置段归剧本仓，不进引擎配置。
- **严格解析**：配置未知键、剧本资产未知字段一律报错；资产载入做形状校验（长度一致性、
  排序约束、索引越界等）。
- **bin 的数据根是代码级常量**（如 `crates/<剧本>-cli/src/main.rs` 的 `DATA_ROOT`），不暴露在命令行；
  lib 侧不写死路径，载入口的根由调用方注入。
- **剧本数据不进引擎仓**（`gamedata/` 是只读输入，仅模板 `templates/umaai-scenario/data/` 保留
  样例资产）；引擎侧不为剧本表新增类型。

## 3. 引擎钩子流程

剧本仓**不 fork、不复制引擎私有逻辑**；缺能力时回引擎加钩子。

| 项 | 规则 |
|---|---|
| 准入判据 | **跨剧本复用**且**与具体剧本、具体算法无关**（「零依赖」只是必要条件） |
| 形态 | **带默认实现、非破坏**；默认实现即旧行为，剧本按需覆写或调用 |
| 申请内容 | 痛点（现在要复制哪些逻辑）、期望形态（签名 / 语义）、默认行为、影响面（是否动基线） |
| 等价性声明 | 提交说明点明**默认行为是否等价**；不等价需重录引擎 L4 基线，并在剧本仓 glossary 记口径 |
| 命名纪律 | `Deref` 底座的方法不得与契约方法同名（基座入口 `init_rule_streams` vs 契约 `set_rule_master`） |
| 复用优先 | 已落地的通用件直接调用，不另写一份（比赛事件构造、训练后默认处理、羁绊出口、红点口径、分桶采样、配置覆盖层 helper） |
| 禁止 | 在剧本仓改引擎源码、把引擎内部类型复制进剧本仓、绕过默认档自建第二套随机对齐 |

## 4. 文档体系

| 文档 | 职责 | 更新时机 |
|---|---|---|
| `README.md` | 仓入口：是什么 / 结构 / 开工步骤 / 文档索引 / 运行与验收 | 结构或验收命令变化时 |
| `AGENTS.md` | 仓内规则：代码结构、数据配置、测试、工具、Git | 规则变化时 |
| `docs/plan/` | 开发计划与决策（阶段状态、接入包、stub 登记、引擎钩子与耦合、策略 / 搜索笔记、性能优化） | 阶段推进、口径拍板、性能改动时 |
| `docs/mechanism.md` | 机制文档：公式 / 流程 / 实现落点 | 机制实现或修正时 |
| `docs/glossary.md` | **术语单一事实源** + 口径与用语决定记录 | 每次口径决定、数值位移时 |
| `docs/tests_overview.md` | 测试一览（分层 + 一行一测试） | 新增 / 调整测试时 |
| `docs/handoff.md` | 交接提示词：当前任务状态、下一步、关键文件与命令 | 对话上下文很长、用户同意交接时 |

- **同步维护**：上表前六项随代码同步维护，在提交准备阶段统一更新；`handoff` 例外，按上下文长度
  在任务完成的适当时刻更新。
- **交接规则**：上下文很长时，可在当前任务完成的适当时刻提示用户向新上下文交接；用户同意后生成
  一段**简短的交接提示词**放在 `docs/handoff.md`，之后可自行开新对话交接，或提醒用户辅助操作。
- **单一事实源**：术语与口径以 glossary 为准，mechanism 只补公式、流程与代码落点，不重复抄术语表。
- **决定记录**：口径差异、与旧实现的分歧、基线位移原因，逐条记入 glossary 的「决定记录」。
- **文档不放绝对路径**，用仓内相对路径或占位符。

## 5. 测试与基线

| 层 | 位置 | 判定 |
|---|---|---|
| L1 单元（私有细节 / 纯函数） | `crates/<crate>/src/` 内联 | `assert` |
| L2 机制集成 | `crates/<剧本>-core/tests/` | 打印 + `Result`（`Err` 即失败） |
| L3 冒烟 | `crates/<剧本>-cli/tests/` | 打印 + `Result` |
| L4 基线 | 仓根 `baselines/` + `<剧本>-sim` 的判定 | 自动判定（比对失败返回 `Err`） |

- **测试 cwd 在各 crate 目录**：数据根 / 基线路径统一经 `<剧本>_core::testing`（`CARGO_MANIFEST_DIR`
  上溯两级定位仓根）取；引擎 `umaai-core::testing` 的 `env!` 固化引擎仓路径，**跨仓不可用**。
- **Release + offline**：测试与 binary 一律 Release；`cargo test` 加 `--offline`。
- **一基线一 JSON**：`input` 自持（不读配置层）、`expect` 逐项（裸值精确 / `{value, tol}` 带容差）、
  `meta` 记版本与日期**不含路径**；重录命令随仓文档写明。
- **数值位移必须留痕**：机制修正、引擎默认档变化、数据升级导致基线位移时，重录基线并在 glossary
  记原因与影响面。
- **可复现守门**：同一 `master` 下两次运行逐位一致；同一根两支分支的差异只来自探测动作。
- **性能回归**：优化改动用配对测量 + 非耗时输出逐位一致验收；工具选择、测量协议与手段清单见
  [`perf_plan.md`](perf_plan.md)。

## 6. 业务分面

按入口归类，两条运行线各由 `cli` 的一档入口承载：

| 业务线 | 做什么 | 终端入口 | 非终端入口 |
|---|---|---|---|
| 离线模拟 | 跑一局 / 批量跑局 / 固定种子基线 / 测卡测量 | `cli` 的模拟档（bin 或子命令） | 宿主直接调 `sim` lib |
| 在线决策 | 吃在线帧、`Session` 一帧一决策、回写决策 | `cli` 的在线档（在线外壳） | Web / Android 宿主调 `ai` lib |
| 人工验证 | 手动 / 交互训练员逐决策选择 | `cli` 的手动档 | — |
| 外围工具 | 测卡 / 复盘 | `tools` 自带单 bin 多子命令（可按需挂 `cli`） | 工具 lib |

- **sim**：只出 lib（基线裁判、批量跑局、测卡测量函数），不承载终端呈现与参数解析。
- **ai**：只出 lib（帧段解析 / 回写、`Session` 接线、决策循环）；依赖与模块在业务落地时登记。
- **cli**：唯一终端 bin 面，负责参数、装配、呈现与退出码；终端依赖（如 `inquire`）只在此 crate。
- **tools**：单 bin 多子命令，复用引擎 `DeckSpec` / `deck` / `arms` 内核与 sim 的测量函数。
- **组卡 / 测卡分层**：通用层只做卡池筛选、构成枚举、配对跑批与统计、呈现；**必带卡、构成约束、
  卡池限定、手写训练员与精确排序归剧本仓**。
- **呈现纪律**：契约 trait 不加呈现方法；剧本资源由剧本自持 View 快照提供，终端呈现原语复用
  `umaai-cli`（样例面）。

## 7. 验收口径

```powershell
cargo fmt --all --check
cargo check --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --release --offline
```

- 上述四档全绿；**引擎仓 `git diff` 为空**（确需新能力时按 §3 回引擎加钩子，禁止 fork）。
- 固定种子可复现：同一 `master` 下两次运行 / 两支分支逐位一致。
- 模板位于引擎仓内时，命令带 `--manifest-path templates/umaai-scenario/Cargo.toml --workspace`；
  复制出仓后从剧本仓根执行。
- CI 守门面与本地一致（fmt / check / clippy / test），工作区为独立 workspace。
