## 2. 核心机制（预告，待续）

### 2.1 人物角标（训练槽的来源）

- 每个人头（**含训练卡（支援卡）与 NPC**；**不含记者 / 理事长**；**友人是否带角标存疑**）
  获得一个**固定角标**，用于积攒对应训练的「槽」。
- 角标类型是否随**卡类型 / NPC id 固定**：**大概率是**（存疑）。
- **点击训练时**，按「当前在该训练的人头」的角标，增加**对应角标**的槽值
  （例：当前有速 / 根角标 → 速槽、根槽同时增加）。
- **彩圈**应有加成；加成范围**存疑**：只加成有彩圈的角标，还是所有角标都加成。

### 2.2 训练槽 / 演出（魂爆）

- 每种训练有一个**槽**，**上限 5**。
- 槽攒满时，该训练的普通训练**临时变为「演出」**（`act`）：
  - 训练类型 id 变化；
  - **基础值**与**上层数值**按**演出等级**大幅提升；
  - 演出等级**上限默认 6**，带友人「吾妻」时提高到 **10**（见 §2.6）；**等级 6 以上**演出训练的
    **基础值 pt 部分可能大幅提升**（幅度与触发档待确认）。
- 点击「演出」= **进行一次更强的训练**；随后该训练**演出等级 +1**、恢复普通训练、
  **槽从 0 重新攒**（一次演出 = 一次强化训练的消耗与结算）。
- 待确认：演出本身是否吃卡片 buff / 彩圈；演出等级提升是否恒为 +1、有无大成功。

### 2.3 分段与结算（check point）

- 机制共 **3 段**，按 0 基回合计（每年 24 回合、决赛期从 72 起，与温泉同口径）：
  - **开始**：turn **2**（「从 0 开始算第 2 回合」）；
  - **第 1 段结束 / 结算**：1 年年底结束时（turn 24，同温泉年末事件口径解析）；
  - **第 2 段结束 / 结算**：2 年年底结束时（turn 48）；
  - **第 3 段结束 / 结算**：3 年 **10 月后半**结束时（turn 67 行动后 / turn 68 回合开始，待真机帧确认）。
- **结算要求**：结算时对**所有训练**的演出等级有**最低要求**，不足时**损失大量剧本加成**；
  需要尽可能满足，**尤其是没带卡的训练位**（角标来源少，更容易不达标）。
- **finals act（决赛演出）**：3 年 10 月结算后**可能还有最终效果**（`finals_act_effect`），
  情报不明，**预计 2026-10-26 明确**。
- 待确认：三次结算的最低要求数值（是否递增）；「损失大量加成」的具体形式
  （加成清零 / 按差额扣 / 扣分）；结算与 `check_point_effect` 表的对应关系。

### 2.4 传授（advice）

- **每段机制开始时**（共 3 次：turn 2 / 24 / 48），为**每一种训练**选择一个**常驻 buff**，
  共 **5 个 / 段**（对应 5 种训练：速 / 耐 / 力 / 根 / 智）。
- 该 buff 对**所有该种训练的卡和 NPC** 生效（`advice` / `advice_effect` / `advice_recommend` 表）。
- buff 类型：**得意率提升、羁绊提升、面板 / hint 提升**等；**类型总数可能 20 种以上**
  （主要影响**词条丰富度**），具体分类与数值**实装后再细化**（2026-10-24 补充）。
- **同时可选的 buff 种类有限**：总池虽大，单次 / 同时可选的种类有限（每段每训练从有限池中选 1 个；
  池子是否固定 / 随机待确认）。
- **进化 buff 替代基础 buff**（确定：进化后替换原基础 buff，**不叠加**）。
- 待确认：每段可选 buff 池规模与是否随机 / 三选一；**同一 buff 能否重复选**（跨段 / 同一训练重复）；
  选择时机与交互（是否也是独立决策点）；NPC / 友人是否同样吃加成；20+ 种 buff 的分类与数值。

### 2.5 融合（fusion）

- **下次剧本结算时**，若「指定演出等级」达标，则**已选择的训练 buff 可以选择进化成更强的 buff**
  （对应 `fusion_effect` 表）；按「下次结算」措辞推断每段 buff 在各自段末结算时可进化一次
  （共 3 次，待确认）。
- **进化 buff 替代基础 buff**（确定：同一位置替换、不叠加；是否允许对同一 buff 重复进化待确认）。
- 待确认：达标线（是单个训练还是全部训练）；每次结算可融合几个 buff；进化后的效果与形态；
  融合是否是可选项（放弃进化是否也受罚）；同一 buff 能否重复选 / 重复进化；决策交互形态。

### 2.6 友人「吾妻」效果（初报）

1. **演出等级上限提升**：上限 **6 → 10**；**6 级以上**演出训练的**基础值 pt 部分可能大幅提升**
   （幅度、是否逐级提升待确认）。
2. **疲劳恢复 flag**：解锁出行时获得新状态 flag「**疲劳恢复**」——**体力 ≤ 49 时，体力 +15**；
   **触发次数 / 持续时间未知**（是否每回合、是否限出行段数、是否与回合数挂钩待确认）。
3. **出行提升最低演出等级**：**友人出行时提高「当前最低的演出等级」**（提升幅度未知）；
   该提升**是否会让对应训练进化（变成演出）未知**。

### 2.7 组卡门禁与推荐配卡（初报）

- **门禁**：编组支援卡 **5 种以上**才触发的门禁效果；效果内容**可能是「进化指导 buff」或
  「finals buff」**（与传授 / 融合 / finals act 的关系待确认）。
- **推荐配卡**：**21101 + 友人**——按项目惯例五类顺序（速 / 耐 / 力 / 根 / 智）即
  **速 2、耐 1、力 1、根 0、智 1 + 友人「吾妻」**，合计 6 张。
- **计数口径推断**：21101 若只数五类训练卡只有 **4 类**，达不到「5 种以上」→ 故「5 种」
  **大概率把友人卡计入**（与温泉仓 `deck_can_split` 的「7 类全算、非零类数 ≥5」口径同源）；
  是否只认支援卡种类待确认。**团队卡在近期剧本里未出现**（用户口径 2026-10-24），miko 大概率
  无团卡、编成为 **1 固定友人 + 5 普通训练卡**。引擎侧已有同口径先例：支援卡固有效果 21 按
  `seen: [bool; 7]` 统计 distinct 卡种（含友人 / 团队），单测「速×2 + 智 + 力 + 友 + 根 = 5 种」。

## 4. 对引擎与当前仓的影响（待办挂接）

- **支援卡 6 张**：与引擎现有假设一致 →
  [`docs/issues.md`](../issues.md) 里「卡数 > 6 / ≤4」的处置条件**未触发**，
  [`open_items.md`](open_items.md) #25「引擎侧卡组长度下限」本轮仍不处置；新剧本落地时再按该条核一次。
- **组卡门禁（≥5 种）**：属剧本档组卡约束（P8b′ 归剧本仓，见 [`open_items.md`](open_items.md) #22）；
  通用层 `umaai-tools::deck::DeckSpec` 现状可表达「必带卡（`fixed`）+ 单类型张数上限
  （`max_per_type`）+ 卡种数下限（`min_types`）」，**`min_types` 已扩为全卡组 7 类口径**
  （含友人 / 团队与必带卡，2026-10-24 落地，见 [`open_items.md`](open_items.md) 近期收口 #33）——
  miko 的「5 种」若把友人卡计入（§2.7 推断），按 `min_types: 5` + 必带友人即可表达
  （21101 + 友 = 5 种）；另有通用原语 `deck::deck_kinds`（全卡组 7 类 distinct 计数）
  供剧本仓门禁校验。**口径存疑（2026-10-24 用户批注）**：实际剧本友人 / 团队卡有且仅有一张、
  且为剧本固定（miko 即 1 友人 + 5 普通训练卡，团队卡近期未出现），组合本体只考虑五类训练卡——
  `compositions` 的 7 类并集实现记为存疑、可能按剧本具体区分（见 open_items #33 存疑注）。
- **友人「吾妻」**：引擎只提供通用友人位（`PersonType::ScenarioCard` / `FriendState` / 出行段状态）；
  「只支持某张友人卡」这类限制按剧本侧策略实现（参考温泉仓的建局校验），引擎不硬编码。
- **数据表**：剧本数据不进本仓（`gamedata/` 是只读输入，剧本数据外置）；这 11 张表的 schema
  属于将来**独立剧本仓**，引擎侧不需要为新表加任何类型。
- **演出等级 / 训练类型 id 变化**：引擎 `TrainingBasicTable = Vec<Vec<[i32; 7]>>` 是**动态等级行数**
  （`[0..4]` 五维、`[5]` 技能点、`[6]` 体力），演出等级 > 5 本身可表达；引擎默认公式已按
  **表实际长度泛化**（2026-10-24 落地）：`default_calc_training_value` 按表行数取行（等级越表
  沿用末行、表外训练点名拒绝）、`calc_training_failure_rate` 的阈值按常量表实际长度夹取、
  基础局 `BasicGame::train_level` 上限取表行数（小合宿拉满 = 表顶）。**仍需剧本侧处理**的只剩
  「训练类型 id ≥ 5」（换 id 的演出训练：默认 buff 计算与 `train_level_count` 仍按五训练口径，
  需覆写）；等级 6→10 的 PT 抬升只需剧本自带多行表数值，无需公式覆写（温泉仓覆写先例仍适用
  于特例公式）。
- **人物角标 / 训练槽**：属剧本私有状态，放剧本局面字段（按人头下标索引）即可，引擎无需改；
  人头类型判断用 `PersonType`（`Card` / `Npc` / `ScenarioCard` / `OtherFriend` / `TeamCard` /
  `Yayoi` / `Reporter`）；彩圈判定可复用 / 覆写引擎 `Game::is_shining_at`
  （默认：支援卡 `train_type` 匹配且羁绊 ≥ 80；团队卡看 group buff）。
- **传授 buff**：三类效果都有现成 seam——得意率走 `Game::deyilv`、羁绊走统一出口
  `BaseGame::add_friendship`、面板 / hint 可经训练值覆写与 `distribute_hint` 覆写落地
  （温泉仓均有先例），引擎无需新增接口。「对所有该种训练的卡和 NPC 生效」按剧本侧过滤人头类型实现。
  若按初报「每训练 1 个常驻 buff、进化即替换」（§2.4 / §2.5），状态形态很简单：
  5 个训练槽 × 3 段，每槽存 buff id + 基础 / 进化态；20+ 总池只是**选择来源**，不构成组合爆炸。
- **结算 / 融合决策点**：属剧本私有非回合决策点（类似温泉仓的源泉选择 `pending_selection`，
  寄生 Begin / AfterTrain 流程），不改引擎；结算门槛应进剧本训练员的守门链与评分
  （低角标训练位要提前补）。
- **疲劳恢复 flag**：与温泉仓「休息心得」（`refresh_mind`）同形态——局面私有 flag + 回合开始
  （Begin）条件回体；注意引擎 `Uma::add_value` 会按 `max_vital` 夹取，若本剧本无超上限体力语义
  则直接用引擎口径即可。引擎零改。
- **出行提升最低演出等级**：友人出行的事件结算特例（温泉仓出行 5 段的券 / 超回复特例为先例），
  剧本私有，引擎零改。
- **剧本仓形态**：届时按 [`docs/scenario/README.md`](../scenario/README.md) 建独立仓（crate 名
  `umaai-miko`？待定），遵守「接入新剧本时引擎 `git diff` 为空」纪律。
