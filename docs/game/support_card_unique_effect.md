# 支援卡固有效果（unique_effect）

> 本文档是《游戏通用规则》(game_rules.md) §10.3 的展开清单，专门记录支援卡**固有效果**的编号体系与映射关系。
> 数据源：`gamedata/cardDB.json`（实机数据）、`scripts/export_support_card/main.py`（ID 映射脚本）、`crates/umasim/src/game/support_card.rs`（AI 端实现）。
> 原始对照表：上游支援卡固有整理表（本地离线表格，A-B 列为词条定义；C-J 列为游戏原始固有；L-O 列为 AI 固有清单）。

---

## 1. 概述

- **固有效果**：部分支援卡在满足条件（羁绊值、编成卡种、体力、训练等级……）时触发，提升自身训练面板或被动词条。
- **数据字段**（`cardDB.json` 每张卡）：
  - `uniqueEffectType`：**AI 固有类型号**（本文档核心，见 §4）。
  - `uniqueEffectParam`：参数数组，长度 6，`param[0]` **始终保留原始游戏 ID**，可用于溯源。
  - `uniqueEffectSummary`：中文摘要，来自游戏原始数据，便于人工查证。
- 类型 `0` 表示无固有效果（直接并入面板）。`cardDB.json` 共 563 张卡，类型分布见 §5.4。

## 2. 两套编号体系

支援卡固有涉及**两套互不相同的编号**，务必区分：

| 体系 | 字段/位置 | 取值 | 用途 |
|---|---|---|---|
| **词条 ID** | Excel A/B 列；`param` 中作为「id」出现 | `0,1,2,…,31,99` | 描述**单个效果词条**，是 `add_effect_line(effect_id, value)` 的入参 |
| **固有类型 ID** | Excel L 列；`uniqueEffectType` | `0..23` | 描述**固有逻辑分支**，是 `calc_training_effect` 的 `match` 分支 |

## 3. 游戏 ID → AI 固有类型 ID 的映射

**权威实现**：[main.py](../../../scripts/export_support_card/main.py#L221-L259) `prepareUniqueEffect(card, ueffect)`。

| 条件（游戏 `type`） | AI 类型 | 说明 |
|---|---|---|
| 无固有，或 `cardId ∈ DirectMergeCards` | `0` | 把固有 `effect` 词条**直接并入** `cardValue[0..5]`，不产生 `uniqueEffectParam` |
| `101` 且 `uniqueParams[1] < 100` | `1` | 羁绊型（阈值 < 100） |
| `101` 且 `uniqueParams[1] == 100` | `2` | 羁绊型（阈值 = 100） |
| `101` 且 `uniqueParams[1] > 100` | — | 打印「新的羁绊型固有」告警（未预期） |
| `102` | `3` | 樱花进王型 |
| `103` | `21` | **特判**：并重排参数 `param[3]=param[2]; param[2]=8`（8 = 训练词条） |
| `104..120` | `type − 100` | 直接映射为 `4..20` |
| `121` 及以上 | `type − 99` | `121→22`、`122→23`（兜底公式） |

要点：
- **`param[0]` 始终保留原始游戏 ID**（`101/102/…/122`），用于溯源与校验。
- **AI 类型 `21` 只能由 `103` 特判产生**，兜底公式 `type−100` / `type−99` 均不会生成 `21`。
- **AI 类型 `23` 是兜底公式自动产物**（`122−99`）：脚本未显式处理游戏 ID `122`，属预期外新增，需人工确认（见 §5.3）。
- `DirectMergeCards = [30155, 30171, 30128]`（[main.py L16](../../../scripts/export_support_card/main.py#L14-L16)）——直接合并面板的特判卡：
  - `30155` [智]大拓太阳神、`30171` [力]春丽、`30128` [智]东商变革。

## 5. 实现细节与已知问题

### 5.1 已实现分支的参数口径

- **1 / 2（羁绊型）**：`if self.friendship >= param[1]` 时，若 `param[2] > 0` 执行 `add_effect_line(param[2], param[3])`；若 `param[4] > 0` 再执行 `add_effect_line(param[4], param[5])`。即最多两条词条。
- **13（闪彩型）**：`if game.shining_count(train) > 0` 时执行 `add_effect_line(param[1], param[2])`。参数 `[113, id, 值]` 直接描述效果。
  > Excel 备注写作「彩圈干劲 60」只是 B95 这一例，实际是通用「参加友情训练时触发任意词条」。
- **20（巨匠型）**：`if self.friendship >= param[2]` 时，统计卡组各卡种数量，对每种存在卡种按 `词条(卡种+3) = count.max(2)` 加成；PT 卡种（`>=5`）走词条 `30`。
- **0**：无操作（固有词条在生成期已 `mergeCardEffect` 并入基础面板）。

### 5.2 未实现分支

Rust 仅接入 `0, 1, 2, 13, 20`；其余（`3–12, 14–19, 21–23`）落入 `_ =>` 分支打印「未实现固有逻辑」。重建（miko_next）时应补齐或明确降级策略。

### 5.3 新发现：AI 类型 23

`cardDB.json` 实测出现 **AI 类型 23**（`30257` [友]塔可布莱恩，`param = [122, 19, 60, 0, 0, 0]`，`uniqueEffectSummary` 为空）。
脚本 `prepareUniqueEffect` 未显式处理游戏 ID `122`，该类型由兜底公式 `122 − 99 = 23` 自动产生。**属预期外产物**，需人工确认其语义（疑似「羁绊 ≥ 60 时提升得意率」一类，待核实）。

### 5.5 Excel L 列与代码不一致说明

`支援卡固有.xlsx` 的 **C-J 列（游戏原始固有）** 与 **L-O 列（AI 固有清单）** 是**两张独立清单，行不保证语义对齐**。例如 Excel 中 `C5=102 → L5=2`、`C6=103 → L6=3`，但代码实际映射为 `102→3`、`103→21`。**映射一律以 `main.py::prepareUniqueEffect` 与 `cardDB.json` 实据为准**，Excel L 列仅作参考。
